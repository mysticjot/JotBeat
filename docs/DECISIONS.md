# Decision Log

Numbered, dated, locked. New decisions append; old ones are amended, never rewritten. ADR.md stays for architecture records; this log is for Creative Director product/pipeline decisions.

## D-0001 — Every JotBeat game is exportable to any platform from day one (2026-08-16, locked)

**Decision:** Exportability is a standing contract, not a release-phase scramble. `python studio/cli.py export` must always produce, from the repo root:

- `dist/web/` — the Vite static build (from `game/dist/`) plus `dist/web/jotbeat-web.zip`, itch.io-ready with `index.html` at the ZIP ROOT. The zip path + size is a required printed output.
- `dist/desktop/` — an Electron thin shell that loads the web build (Windows first; mac/Linux same pipeline).
- `dist/mobile/` — a Capacitor thin shell (`webDir` → web build, Android first).

The web build is the single artifact and always works standalone; wrappers are thin shells around it. Exit 0 requires only web build + zip — wrapper failures degrade to printed FLAGs, never hard failures. CI runs export with `JOTBEAT_EXPORT_WRAPPERS=0` (scaffold-only, keeps CI fast) and asserts the zip exists and is non-empty.

## D-0002 — Wrapper tool choices and the platform adapter rule (2026-08-16, locked)

**Decision:**

- **Desktop: Electron.** Tauri was considered only if a Rust toolchain (`cargo`) is present; Electron is the locked default because it needs nothing beyond npm. Wrapper deps live in repo-root `desktop/`, never in `game/package.json` (would bloat every CI `npm ci`).
- **Mobile: Capacitor** (`@capacitor/core` + `cli` + `android` in repo-root `mobile/`), `webDir` pointing at the web build. Same rule: not in `game/package.json`.
- **Platform adapter rule:** game code must NEVER import wrapper APIs (Electron, Capacitor) directly. All platform features go through `game/src/platform/` (`save`, `load`, `requestFullscreen`, `haptic`), whose WEB implementation (localStorage, Fullscreen API, `navigator.vibrate`) is the always-working default fallback. Wrappers inject their own implementation via `setPlatformAdapter()` at boot. The adapter is the contract.

## D-0003 — Door-threshold: opening a door requires a square approach (2026-08-16, locked)

**Decision:** The locked door's physics body stays a full-tile static blocker, but the open trigger is gated: `Game.openDoor` only fires when the player's center is aligned with the door's center within `DOOR_APPROACH_TOLERANCE` (12px) on the approach axis. A diagonal graze clipping the door body's corner no longer consumes the key. On open, the door swaps to the `door-open` texture and its body disables cleanly.

## D-0004 — Map layout is generated, not hand-edited (2026-08-16, locked)

**Decision:** `game/maps/build_map.py` is the single source of truth for the dungeon layout (floor rects + derived wall shell + gameplay anchors) and emits BOTH `game/maps/dungeon.ldtk` (LDtk 1.5.3, for viewing) and `game/assets/maps/dungeon.json` (Tiled, for Phaser) — the two cannot drift. Hand-editing either output is void. Gameplay anchors move only by moving them in the generator and syncing `LAYOUT` in `Game.ts` and the spec waypoints.\r

## D-0005 — Engine and stack of record (2026-08-16, locked)\r
\r
**Decision:** The tech stack is stated here so no one infers it from bug reports. **Engine: Phaser 4.0.0** (exact pin in `game/package.json`; NOT Phaser 3 — v3 API patterns are rejected per AGENTS.md §3 and ADR-0002). Language: TypeScript ~5.7.2. Build: Vite ^6.3.1 (`vite/config.dev.mjs` / `config.prod.mjs`). Test: Playwright ^1.62.1 + pixelmatch/pngjs for visual baselines. Map pipeline: LDtk 1.5.3 (viewing) + Tiled JSON (runtime), both generated by `game/maps/build_map.py` (D-0004). Wrappers per D-0002: Electron (desktop), Capacitor (mobile). Studio: Python (stdlib-first), LangGraph orchestrator. If any of these versions change, this entry is amended in the same commit.\r

## D-0006 — Agent harness strategy and observability rulings (2026-08-17, locked)\r
\r
**Decision:**\r
\r
- **The JotBeat brain (LangGraph orchestrator, `studio/orchestrator.py`) is the control plane / meta-harness.** It owns task flow, gates, escalation ceilings, and the ledger.\r
- **LangChain Deep Agents is the execution harness**, integrated in-process on the existing brain. Roles run as sub-agents with planning, a virtual filesystem, a sandboxed shell, and permission-scoped tools (auditor reads only; narrative writes text only). Models come ONLY from `studio/providers.json` via `models.py` family dispatch — no hardcoded providers, no parallel key stores.\r
- **OpenHands is reserved for heavy sandboxing** (untrusted or destructive workloads). Not adopted by default.\r
- **dsh, Omnigent, and ACP are tracked, not adopted** — no adoption without Creative Director sign-off.\r
- **LangSmith is REJECTED** — redundant with `state/events.jsonl`. Its env keys (LANGCHAIN_TRACING_V2, LANGCHAIN_API_KEY, LANGCHAIN_ENDPOINT) must never be set; tracing env is explicitly disabled in harness code.\r
- **Langfuse (self-hosted) is pre-approved** if dashboards are ever needed — it would read the same ledger truth, not replace it.\r

## D-0007 — Animation pipeline: build, not rent (2026-08-17, locked)\r
\r
**Decision:** JotBeat builds its own 2D animation pipeline (`jotbeat anim`) instead of renting SaaS tooling:\r
\r
- **Layer segmentation:** OpenCV connected-components layering of a transparent character PNG.\r
- **Rig/skinning:** DragonBones (open-source 2D skeletal runtime, JS) — rig data in JSON, DragonBones-format-compatible; we do NOT roll skinning from scratch.\r
- **Retargeting:** BVH→2D retargeter over free mocap — CMU Graphics Lab mocap + Ubisoft La Forge (LaFAN) BVH clips — projected to 2D with normalized bone lengths. BVH parsing via an existing Python library, never hand-rolled.\r
- **Bake:** headless render to Phaser sprite sheets.\r
- **Provenance:** mocap clip IDs recorded in `game/assets/manifest.json` like any other asset.\r
- **Charios stays REJECTED for production** (SaaS license risk) unless the spike hits a wall — then the wall is reported, not silently switched around. **Sprite Fusion stays contingency-only** (as previously logged).\r
\r
## D-0008 — Studio tools are departments (2026-08-17, locked)\r
\r
**Decision:** "Studio tools are departments — reusable, config-driven, genre-agnostic. A tool that only serves the current game is a defect in the tool." JotBeat is the product; games are its output. Every tool is a permanent studio department, never a per-game prop:\r
\r
- **Animation Department:** `jotbeat anim` — input: any character/prop art conforming to a game's style card; output: engine-ready animation sets (idle/walk/run/attack as config, never hardcode). Game-agnostic, provenance-logged, CI-runnable. SALTBOUND is its first customer, not its purpose.\r
- **Level Department:** the map builder (`game/maps/build_map.py` pattern) generalizes beyond one dungeon.\r
- **Sound Department:** the audio pass (sourcing, provenance, config-driven volumes).\r
- **Art Department:** the art bible + conformance scan (`docs/ART_BIBLE.md` style lock, palette scan).\r
\r
Department heads are the existing studio roles (Art Director owns anim/art tooling, etc.). New games commission the departments; they don't rebuild them.
